# 三平台内容准备与草稿交付

## 当前目标

2026-09-19 用户要求在原有 Edge 草稿交付按钮中增加逐站选择。每篇可选个人站、公众号、小红书中的任意一至三个，未选站跳过生成、存稿与回读。最终仍由用户审核并触发发表。Codex 和 skills 负责创作输入；按钮执行渲染、存稿和回读，不保证网络、登录或平台校验失败时仍全部成功。

| 平台 | 草稿位置 | 最终发表 |
| --- | --- | --- |
| 个人站 | 本地内容项目、版本包及仅监听本机的 Astro 预览 | 用户确认后执行部署；没有站内后台草稿箱或发布按钮 |
| 微信公众号 | 官方平台草稿箱，API 保存／更新后回读 | 用户在公众号后台手动发表，不群发 |
| 小红书 | 日常 Edge 指定 profile 的图文草稿，回执绑定扩展实例和账号 | 用户在后台手动发布；不调用公开发布 |

第一篇网站文章已在用户明确确认后公开，不会因目标调整自动撤下。以后 `prepare` 不修改线上站点，也不把未审核文章加入公开内容目录。

## 每期内容项目

在 `content-projects/<id>/` 集中管理本期。原始资料放 `sources/`，唯一工作稿为 `article.md`，正文附件放 `assets/`，小红书改写放 `xiaohongshu.json`，最新平台稿放 `platforms/`。详细结构见 [目录说明](../content-projects/README.md)。

`article.md` 元数据包含 title、description、publishedAt、tags、featured、status: draft；引用整理可增加 source.label/url/checkedAt、contentNote。小红书 JSON 的 sourceHash 必须匹配工作稿，不能只改指纹跳过内容检查。

程序只对工作稿、小红书脚本、正文附件及渲染代码计算版本指纹；原始资料、平台回读、说明文件和实验图片不作为渲染输入，避免保存回执反过来使工作稿版本变化。

## 使用过程

1. 创作前先确定本期目标平台，写入本期 project.json 的 distributionDecision.selectedPlatforms。用户已明确说只发某站时直接沿用；未明确时 Codex 先询问，再创作平台专用稿件。可以提前整理共用素材，不默认生成三份稿。
2. Codex 完成 `article.md` 和附件；选中小红书时使用 `baoyu-xhs-images` 制定本篇方案、保存逐图提示词并调用真实生图后端，审阅最终图片，然后完成 `xiaohongshu.json` 文案与图片清单。未选小红书时不生成其文案和配图。缺图或过期输入只影响小红书，不阻塞未选择它的任务。
3. 运行 `npm run content:hub`。在日常 Edge 点击「LUI 三站草稿交付」，选择本期，勾选目标平台，点击「交付所选草稿」。新项目默认不勾选；每篇的选择记在当前 Edge 扩展存储中。空选不能提交。
4. 服务只生成所选平台的内容包。选择网站时保存到 `platforms/website/draft/`；选择公众号时使用官方 API 新增或回读已存在的人工稿；选择小红书时扩展填写图片、标题和正文，点「暂存离开」后重新打开核对。未选站不访问、不写入，也不删除或覆盖已有草稿。
5. 所选平台都显示「草稿已核实」才算完成，其余显示「本次未选择」。部分失败保留成功项。包含网站稿的版本可用 `npm run content -- preview <id>` 审核，默认地址 `http://127.0.0.1:4322`；停止 Astro 预览后再执行普通构建和检查。
6. 用户审核后，在公众号和小红书后台手动发表；网站由用户明确触发部署。最终发表不属于默认草稿流程。

低层 `content prepare` 仍是纯本地命令；必须显式选择平台，用 `--platforms wechat` 只生成公众号包，用 `--platforms website,xiaohongshu` 生成两个平台。未包含网站的版本不能启动网站预览。交付页勾选是执行前的范围确认，不是创作后再删除未选稿件。

小红书固定文字卡片代码已移除。`baoyu-xhs-images` 在创作阶段由 Codex 实际执行，按内容动态选择视觉方案；在当前 Codex 环境默认使用原生 imagegen。按钮不调用模型，只校验和打包已经完成的图片。再次交付可复用已审核图片，不等于重新生图。原文截图作为证据保留，不自动重绘、遗漏或改成文字卡片。

## 小红书图片输入

本期 `xiaohongshu/` 保存 skill 的 `analysis.md`、`outline.md` 和创作记录，`prompts/` 保存生图前落盘的完整提示词，`images/` 保存最终审核图片及原图副本。不要把专用图片或提示词放通用 `assets/`，否则可能混入网站和公众号的附件。

`xiaohongshu.json` 的最小格式如下。`sourceHash` 是当前 `article.md` 完整文件的 SHA-256；顺序决定上传顺序，第一张为笔记首图。所有文件引用均相对于本期项目目录：

```json
{
  "sourceHash": "<article.md的64位SHA-256>",
  "title": "本篇小红书标题",
  "caption": "已经审阅的本篇文案",
  "imageSkill": "baoyu-xhs-images",
  "images": [
    {
      "kind": "generated",
      "path": "xiaohongshu/images/01-cover.png",
      "prompt": "xiaohongshu/prompts/01-cover.md",
      "alt": "本篇动态生成的封面"
    },
    {
      "kind": "original",
      "path": "xiaohongshu/images/02-screenshot.png",
      "alt": "原文客户端截图"
    }
  ]
}
```

清单支持 1–18 张静态 PNG/JPEG/WebP。生成图必须有实际存在且非空的 `.md` 提示词，原图不要求伪造提示词。路径不可越出本期目录，不接受链接目录、SVG、动画或伪装图片。内部校验限制单文件 32MB、4000万像素；这是交付器的处理上限，不是平台权益声明。JPEG/WebP 仅做方向校正与 PNG 格式转换，不在交付阶段排字、裁切、拼图或改写图片。普通 PNG 保持原字节；带元数据或方向信息时规范化处理。文件清单仍使用 `cards/01.png` 等旧传输命名，以兼容图片顺序和字节/像素回读校验，这不再代表固定卡片渲染。

原图、提示词和 JSON 均参与本期来源指纹，缺图会停止小红书准备，绝不回退文字模板。`imageSkill` 是创作来源声明，不能独立证明执行过 skill；真实工具结果和创作记录才是调用依据。提示词不会随图片上传或进入网站公开稿。

旧 `cards` 文本输入不再用于新生成，遇到会提示重新通过 skill 完成图片清单。历史包与未知提交回读保留，不能把旧固定模板图片直接换个来源标签冒充本轮 skill 生图。已发表或已撤回内容不自动迁移或重新交付。

## 首次配置 Edge 按钮

1. 使用 Node.js >=22.12，在仓库根运行 `npm ci`。公众号还需已安装 `baoyu-post-to-wechat`、已配置凭据和可用 API/SSH 出口；程序通过 `npm exec --yes -- bun` 启动其传输适配器。
2. 运行 `npm run content:hub`。服务固定只监听 `127.0.0.1:4389`；端口冲突时报错，不另开公网地址。连接码自动保存在 `.content/delivery/connection.txt`，重启服务后保持有效，不输出到日志。
3. 在日常 Edge 打开 `edge://extensions`，启用开发人员模式，点「加载解压缩的扩展」，选仓库下 `extensions/draft-delivery/`。这是本地开发扩展，未提交应用商店。步骤依据 [Microsoft Edge 扩展侧载文档](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/getting-started/extension-sideloading)。
4. 点扩展打开交付页，填写本地连接码。只选网站/公众号时无需小红书账号；选择小红书时填写 profile 备注及右上角账号显示名称。点击「连接并保存」。连接码只保存到该 profile 的扩展私有存储，不发送给小红书页面。
5. 在同一 Edge profile 登录小红书创作平台。不同 profile 的实例 ID 不同，不能用另一浏览器的旧回执充当本次成功证据。

关闭内容服务所在终端会停止服务；下次重新运行同一命令。关闭交付页暂停浏览器步骤，但任务 JSON 留在 `.content/delivery/jobs/`。更新扩展代码后，在 Edge 扩展管理页重新加载扩展，再刷新交付页。

升级到 0.3.0 时同时重启 `content:hub` 并重新加载扩展。旧客户端没有提交平台选择会收到明确错误，不会被新服务默认为三站。平台勾选只控制当前任务，不代表公开发表授权。

扩展只申请本机 HTTP 服务、小红书创作平台、扩展私有存储和页面脚本权限；不申请 Cookie、浏览历史、调试器或所有网站访问权限。服务所有内容接口均校验连接码、Host 和 Origin，不能从普通网站调用。公众号密钥保留在用户级 Baoyu 配置中。

## 重复交付、人工修改与恢复

- 同一版本、同一平台组合及相关 Edge 目标重复点击复用同一任务；平台顺序不影响复用。只有选中小红书的任务需要 Edge 目标；即使旧记录成功，也重新核对浏览器草稿，避免清除浏览器数据后误报成功。
- 小红书只编辑扩展新建的独立标签页，保护用户原来的未保存编辑页。保存前先在服务落盘一次操作许可；重开页面后若结果未知，只回读。草稿标题重复、正文不同、图片文件或顺序不同都停止，不覆盖。
- 草稿列表必须切到「图文笔记」且加载完整；保存后重新打开，核对标题、规范化空白后的完整正文和逐张图片顺序。先比较文件 SHA-256；小红书无损重编码导致字节不同的，再用同一浏览器解码原图和草稿图，要求尺寸及每个 RGBA 像素完全一致。不会用模糊相似度或仅看图片数代替核验；仍不同则保留草稿与本地诊断图，停止确认。
- 小红书保存和打开草稿会完整重载页面，操作与回读在不同的页面上下文执行。只读查找/回读被页面重载中断时，最多重新连接三次；上传和保存动作不自动重试。扩展优先复用本任务的非编辑检查页，保留可能正在由用户修改的编辑页。
- 公众号已有 `mediaId` 时先回读最新内容；原稿来源指纹相同可保留平台人工定稿，原稿变化则提示合并。初次新增成功后先落盘 mediaId 再回读；超时且没有 ID 时禁止自动再建一篇。
- 公众号已发表后，旧草稿 ID 可能返回 40007。按钮会提示旧草稿已不在草稿箱，不自动复制一篇。确需重建时先明确授权，归档原草稿回执/操作记录，并把最后审核 HTML、封面及来源/正文指纹绑定到本期 `project.json` 的 `delivery.wechat.reviewed`；新建后比较标题、正文、提示词与图片，保留新的 mediaId。本文首篇已按用户授权重建一次验收草稿。
- 网站 `draft/` 与既有公开交付记录分开；工作稿或附件在目标目录被人工修改时停止覆盖。需要从工作稿生成新内容时，先把人工改动合并回创作输入。
- 「继续核对本次交付」按原任务 ID 恢复。即使后续改了工作稿，仍可核实原版本的未知小红书保存。成功表示该任务版本交付成功，不代表后续修改也已交付。
- 恢复任务始终使用该任务保存的平台选择；修改复选框只影响新任务。新任务选择会参与内容版本与任务标识，未选平台状态为 `skipped`。旧 version 1 包和任务保留三站语义，历史包仍可核验，已变更模板的旧包不能被当成当前版本重新提交。
- 同一篇、同一 Edge profile 有小红书保存结果未知时，不能通过换平台组合、改文案或改账号备注绕过。新建任务与领取保存许可都会检查；不选小红书的独立任务可以继续。

三站不能跨系统做数据库事务：某站失败不会自动撤销另外两站的草稿。不要通过删除原稿、关闭安全检查或重新提交来处理未知结果。

## 公众号已验证的方法

用户级 Baoyu 配置提供凭据、SSH 出口和主题偏好，不把密钥放到仓库。remote-api 使用 SSH SOCKS 转发到官方 API；ECS 只允许指定用户转发到 api.weixin.qq.com:443。白名单填实际出口 IP。网站的 DNS、80/443 与公众号白名单是不同设置。

读取已有草稿：

```bash
npm run wechat:draft -- read <id>
```

它刷新本期 `platforms/wechat/draft.json`、`body.html`、`preview.html` 和 `receipt.json`。更新已有草稿时，先生成正文片段，并使用最近回读的 bodyHash 防止覆盖新的人工作业：

```bash
npm run wechat:draft -- update <id> <正文HTML路径> <bodyHash>
```

更新命令不公开发表，保存后必须回读。结果未知时先查询，不重复提交。若平台返回空的封面素材 ID，先核对当前封面；不能用旧封面覆盖用户新封面。之前的 40007 由此触发，补齐当前封面的有效素材后才成功。

已验证的排版约束：

- Baoyu 草稿 API 的成功表示存稿，不表示公开发表；旧草稿箱开关接口已废弃，无需找开关。
- 当前账号保存稿时，将正文可点击外链改为文字并保留底部来源 URL，移除装饰 SVG；仅压缩长度未解决 45166。
- 项目主题 `editorial-orange` 由 `scripts/content/wechat-editorial-theme.mjs` 后处理，不是 Baoyu 原生主题参数，不应直接写进其 default_theme。
- 保留 12 段提示词字面，引用编号连续且正文对应；正文引用不使用角标；公众号不放无效 JS 复制按钮。
- 列表已有文字圆点时关闭原生 marker，避免重复；字体使用完整、可回读的行内属性。
- 浏览器工具对网站的拒绝不能通过换浏览器、CDP 或抓取脚本绕过。官方 API 工作不依赖后台浏览器登录。

## 版本与状态

`.content/` 只保存程序生成的版本包、状态、清理回执和恢复快照。`content-projects/<id>/platforms/` 保存用户可以直接审核的最新平台稿；生成包的默认 HTML 不一定等于后来人工修改的公众号定稿。

`npm run content -- status <id>` 查看版本账本。`content record` 只登记已观察事实，不执行上传或发表。新生成版本不继承旧版本批准；已经发生的平台交付仍保留在原版本账本及本期平台回执中。

清理采用先预览后执行：

```bash
npm run content:prune -- <id>
npm run content:prune -- <id> --apply --plan <planHash>
```

保护当前、上一版、平台记录和文档引用，包括缩写版本号。人工修改或不完整包不自动删除；清理摘要保存在 `.content/pruned/`，不是完整恢复备份。

统一交付任务和私人内容项目中的平台回执也参与引用保护；尚待核实的历史内容包不能被清理。`skipped` 与 `local_ready` 都不单独构成平台交付历史。当前扩展版本为 0.3.0，验证与验收状态见 [逐站交付与图片创作结果](development/2026-09-19-selective-draft-delivery-result.md)；0.1.3 的既有实测记录保留在 [早期结果](development/2026-09-12-unified-draft-delivery-result.md)。
